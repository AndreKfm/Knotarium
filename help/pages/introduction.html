What is Knotarium?

Knotarium is self-hosted workflow automation that you build by drawing. Instead of writing a script that calls an API, checks a result and sends an email, you place those three steps on a canvas, connect them, and press Run. The result is something you can watch execute, step through afterwards, version, and hand to someone else.

The shape of the product

Everything is one program. A single .NET process serves the API and the user interface, and stores its data in one local SQLite file. There is no database server to install, no Node.js runtime, no message broker, and no cloud account. You can run it from a folder, as a Windows service, or as a container, and the whole thing is a few hundred megabytes on disk.

That matters most when things go wrong: there is exactly one process to restart, one file to back up, and one log to read.

The vocabulary

Five words carry most of the meaning in this documentation, and they are worth pinning down before anything else.

  • Workflow — the graph you draw. It is the unit you save, publish, share and enable.
  • Node — one step. Sending an HTTP request, querying a database, branching on a condition, writing a log line.
  • Edge — a connection from one node's output to the next node's input. Edges carry both the flow of control and the data.
  • Trigger — what starts a run: a manual click, a schedule, an inbound webhook, a poller that watches a source, or an error elsewhere.
  • Run — one execution. Every run is recorded step by step, which is what makes the debugging tools possible.

What makes it different

The logic is real C#, compiled as it runs

The Inline Code node and custom node packages are genuine C# compiled at runtime, not a scripting dialect bolted on for configuration. That is a real capability and a real risk, which is why code execution is switched off until an administrator turns it on.

You can step backwards through a finished run

Because every run is journaled node by node, the inspector can show you what each node received, what it produced, and what the variables looked like immediately before and after it ran — for a run that finished days ago. When a workflow misbehaves you are reading a recording, not reproducing a bug.

AI output passes through deterministic gates

Alongside the usual prompt and routing nodes, two nodes turn a language model's answer into structured findings that ordinary code then judges. A claim with no supporting evidence is marked unsupported rather than being quietly accepted. The decision to continue is made by your rule, not by asking a model whether it thinks it did well.

Dangerous things are off until you switch them on

File access is denied by default and granted one directory at a time. Code execution and database access are disabled until enabled explicitly. Outbound requests are checked against an egress policy that blocks internal addresses. Importing a workflow that contains a privileged node asks you to acknowledge it first.

Treat a running instance as privileged

Knotarium exists to execute code and touch systems on your behalf. Anyone who can reach the interface can eventually make it do those things. Do not put an instance on the public internet without your own authentication layer in front of it, and be deliberate about who holds an account.
