Keyboard shortcuts

The complete keyboard map. The editor carries an abbreviated version of this list built in — press ? anywhere on the canvas to see it — but that sheet covers the canvas only. This page also documents the keys bound inside the search palette, the run inspector, the code editor and the other panels, which the sheet does not list.

The cheat sheet built into the editor

Pressing ? toggles a panel titled Keyboard shortcuts over the canvas. It is rendered directly from the same shortcut table this page is written against, so it cannot drift from the handlers. Press ? again or Esc to close it, or use the close button in its corner.

Opening the sheet is suppressed while the focus is in a text field, so typing a question mark into a node's property still types a question mark. Closing it is not suppressed: once the sheet is open, ? dismisses it from anywhere.

Ctrl and Command are interchangeable

Every shortcut on this page that shows Ctrl accepts Ctrl or ⌘, on every platform. The handlers test for either modifier rather than branching on the operating system, so ⌘Z works on a Mac keyboard plugged into Windows and CtrlZ works on macOS.

The platform difference is one of display, not behaviour. The in-app cheat sheet detects macOS and prints ⌘; everywhere else it prints Ctrl. Detection prefers the browser's modern platform hint and falls back to the older platform string and then the user-agent, so an unusual browser may show the Windows labels on a Mac — the keys themselves still work either way.

Two ways to open node search

CtrlF and CtrlK do the same thing. The pair exists so that the habit from a text editor and the habit from a command palette both land in the right place. On macOS ⌘K is the one usually reached for.

Canvas: navigation

KeysAction
CtrlF or CtrlK Open the node search palette and jump to a node by name.
CtrlShiftH Toggle the version history panel. Shift is part of the combination deliberately: a bare CtrlH opens the browser's own history, and ⌘H hides the application on macOS.
? Toggle the built-in shortcut sheet.
Esc Clear pinned highlights, cancel a connection you started by clicking a port, and leave a read-only version preview.

Esc carries the most meanings of any key here, and it applies them in a fixed order. It always clears the variable pins and abandons a half-drawn connection. Only then, and only if you are looking at a read-only preview of an older version and no dialog is open above it, does it back out of that preview and return you to the live draft. A dialog that is open owns Esc for itself, so pressing it twice — once to close the dialog, once to leave the preview — is the expected rhythm.

Canvas: editing

KeysAction
CtrlZUndo.
CtrlShiftZ or CtrlYRedo. Both are bound; use whichever your other tools use.
CtrlCCopy the selected nodes and the edges between them.
CtrlVPaste the copied selection.
CtrlDDuplicate the selection in place. This also suppresses the browser's bookmark dialog.
CtrlASelect every node on the canvas.
Delete or BackspaceDelete the selected nodes and edges. Deleting a node also removes every edge attached to it.

Copy and paste are handled inside the application rather than through the system clipboard, so a selection copied on one canvas can be pasted onto another canvas in the same browser session but not into a text editor. Deleting takes a single undo snapshot before it removes anything, so one CtrlZ restores the whole deletion including the edges.

Canvas: selecting, panning and zooming

The canvas is built on a flow library whose default mouse and modifier conventions apply unchanged, with three deliberate overrides. Nothing here is remappable.

GestureAction
Drag on empty canvasDraws a selection box. The box selects anything it touches, not only what it fully encloses.
Middle-drag or right-dragPans the canvas. The left button is reserved for the selection box, so panning is deliberately on the other buttons.
Ctrl + click ⌘ on macOSAdds a node or edge to the current selection instead of replacing it.
Shift + dragDraws an additional selection box that adds to the current selection.
Scroll wheelZooms.
Double-click empty canvasZooms in one step.

This is the one place where the modifier genuinely differs by platform: the add-to-selection modifier is ⌘ on macOS and Ctrl everywhere else, and unlike the application's own shortcuts the two are not interchangeable here.

When a shortcut is ignored

Most canvas shortcuts stand down while you are typing. If the focus is in a text input, a text area, a select, or any element marked as editable, then undo, redo, copy, paste, duplicate, select-all, delete and ? are all left to the field so that CtrlZ undoes your typing rather than your last node placement.

Three shortcuts are exempt and always fire, on the reasoning that they must be summonable from anywhere:

  • CtrlF and CtrlK — the search palette owns its own input once it opens.
  • CtrlShiftH — the version history panel.
  • Esc — always clears pins and cancels a pending connection.
Dialogs seal themselves off

The Inline Code editor, the search palette and the node rename field stop keystrokes from reaching the canvas at all rather than relying on the typing check. Without that, pressing Space in the code editor would pan the canvas behind it and Backspace would delete the node you were editing.

Panels, palettes and dialogs

These keys are bound by individual panels and are live only while that panel has focus. None of them appear on the in-app cheat sheet.

Node search palette

KeysAction
↓ / ↑Move the highlight. Both wrap around the ends of the list.
EnterJump the canvas to the highlighted node and close the palette.
EscClose without jumping.

Version history and the version dropdown

In the version history panel, each version row is reachable by Tab, and Enter or Space previews that version — the same as clicking it. Previewing is read-only and never changes what runs.

The runtime version dropdown in the toolbar is a full keyboard combo box:

KeysAction
↓, Enter or Space when closedOpen the list with the current version highlighted.
↓ / ↑ when openMove the highlight and immediately preview that version on the canvas. The highlight stops at the ends rather than wrapping.
Enter when openCommit the highlighted version as the selection.
Esc when openClose the list and revert the preview to what was showing before.

Run inspector

While the step-through inspector is open over a finished run, the arrow keys walk the recording:

KeysAction
← / →Previous and next step. Both stop at the ends of the run rather than wrapping.
EscClose the inspector.

In the run timeline beside it, each journal row is focusable and Enter or Space selects that step, which is what drives the highlight on the canvas.

Inline Code editor

KeysAction
EscClose the editor. With unsaved changes this raises the confirmation sheet instead; a second Esc dismisses that sheet without closing.
CtrlEnterIn the Generate with AI description box only, submits the prompt.
. or "Opens the C# completion list as you type.

The code surface itself is a standard Monaco editor with no custom key bindings added, so its own defaults — completion on CtrlSpace, comment toggling, multi-cursor, find and replace — all behave as they do in any other Monaco-based editor. Because the whole modal swallows keystrokes, none of them reach the canvas.

Condition editor

The full-screen condition editor is opened with Enter or Space on the condition card in the properties panel, or by double-clicking a Condition node. Inside it, Esc closes the innermost thing that is open: the operator menu first, then the value editor popover, and only when neither is open does it leave the editor. Leaving with unsaved changes asks for confirmation first.

Drop-downs, comboboxes and expression fields

ControlKeys
Expression fields, while the completion popover is showing ↓ / ↑ move through completions and wrap; Enter or Tab inserts the highlighted one — Tab is intercepted, so it does not move focus while the popover is open; Esc closes it. ←, →, Home and End re-offer completions for the new caret position.
Template and workflow pickers ↓ / ↑ open the menu and move through it; Enter or Space choose; Esc closes.
The OpenAPI operation picker ↓ / ↑ move through search results; Enter chooses; Esc closes.
Searchable select menus elsewhere Esc closes. These have no arrow-key navigation — use the search box and the mouse.
Fields offering a manual fallback value Enter commits what you typed.

Rename fields

Node titles, group titles, workflow names, workspace group names and variable names all rename the same way: Enter commits and Esc cancels. Clicking away commits rather than cancelling. Renaming a workflow or a workspace group to an empty string restores the previous name instead of saving a blank.

Mouse gestures worth knowing

Several actions have no keyboard equivalent at all and are only reachable with the pointer.

GestureAction
Double-click a Sub-flow nodeOpens the referenced workflow on its own canvas, saving the current draft first. The arrow badge on the node does the same thing with a single click.
Double-click an Inline Code nodeOpens the code editor.
Double-click a Condition nodeOpens the full-screen logic editor.
Double-click a node's titleRenames it. The same works on a group's title.
Drag a node onto an existing wireInserts the node into that connection, splitting the edge in two.
Tab to a port, then Enter or SpaceStarts or completes a connection without a mouse. This is the one connection gesture that is reachable from the keyboard.

Toolbar actions with no key binding

The in-app sheet lists these under a Layout heading, which reads as though they were shortcuts. They are not — they are toolbar buttons, listed there so the layout tools are discoverable:

  • Tidy — auto-arranges the graph from left to right.
  • Grid — toggles snap-to-grid.
  • Align and Distribute — appear only once two nodes are selected; distribute needs three.
Opening the canvas disarms the runtime

No key does this, but it surprises people often enough to belong on any page about the editor: entering the canvas automatically disarms the runtime so that a draft you are part way through editing cannot fire on a schedule. Re-arming is a deliberate click on the header switch. See Runtime arming.
