The canvas editor

The canvas is where a workflow is drawn: nodes on the left, the graph in the middle, the selected node's properties on the right. This page covers the parts of that screen that are not obvious from looking at it — how wiring actually behaves, which gestures are destructive, what the layout tools do to your positions, and the one side effect of opening the editor that surprises everybody.

Opening the editor

There are two ways in, and they do different things. Opening a workflow from the dashboard loads that workflow. Clicking Canvas Editor in the header always starts a new, empty workflow containing a single Start node — it does not return you to whatever you had open. Coming back to a workflow you were editing means going through the dashboard again.

The editor remembers where you were looking. The viewport (pan and zoom) is stored per workflow in browser storage, so re-entering a graph lands where you left it rather than re-centring. If the stored viewport would leave the graph off screen — which happens with graphs at negative coordinates — it is discarded and the graph is framed instead.

Entering the editor disarms the runtime

The moment the canvas editor opens, Knotarium switches the global runtime arming switch to Disarmed. This is deliberate — editing is treated as design time, and a half-wired graph should not be firing on a schedule — but it is silent apart from the header badge changing from Armed to Disarmed.

It does not re-arm when you leave. Schedules, webhooks, pollers and device events stay paused until you click the switch in the header yourself. If a scheduled workflow "stopped working" shortly after somebody opened the editor, this is almost always why.

The node palette

Nodes are grouped into six categories — Trigger, Logic, Data, Network, AI and Utility — derived from each node package's declared category. Above them sits a Recent / Pinned panel, and below them a Templates panel and a collapsed Advanced panel. Advanced holds nodes whose manifest marks them as escape hatches; it starts collapsed so the ordinary building blocks are the obvious choice.

The search box filters on what you can actually read on the card: the node's display name, its description and its category. It deliberately does not match the internal node id, because matching ids produced results nobody could explain. Several words are combined with AND, and while a search is active panels with no hits disappear entirely rather than stacking up empty headers.

The pin button beside each node adds it to Recent / Pinned permanently; nodes you have recently placed appear there on their own. Panels themselves can be reordered by dragging the grip at the left of a panel header, and that order is remembered in browser storage per browser, not per workflow.

Three node types are registered but not offered

Sticky notes and groups are inserted from the canvas toolbar rather than dragged from the palette, so they are hidden here. The old manualTrigger node is hidden too: it duplicates what Start already does. Existing workflows that contain one still render and still run — only the palette stops offering it.

Placing nodes

Clicking a palette entry drops the node at an automatically chosen position. Dragging it onto the canvas places it exactly where you release, which is almost always what you want, because several placement behaviours key off where the node lands:

  • Dropped on an existing wire, the node is spliced into that connection: the wire is cut and re-routed through the new node, as a single undo step.
  • Dropped into a loop or parallel container, the node becomes a child of that container and moves with it. If the container was empty and the node is not a trigger, it is auto-wired from the container's start to the node and back to the container's end, giving an immediately runnable single-step body. Once a container has children, nothing is auto-wired.
  • Dropped in open space, a proximity check runs: a free output port close to a free input port on a neighbouring node connects automatically. Ports that would connect glow while you drag.

Dragging a node out of a container detaches it again. Containers, group boxes, sticky notes, Start and Scheduler nodes are never reparented by a drag.

Templates are dragged from the palette the same way and stamp a whole subgraph at the cursor. A template with a required parameter that has no default cannot be satisfied mid-drop, so it opens the Insert panel instead and says so in the status bar.

Connecting nodes

A connection always runs from an output port on the left-hand node to an input port on the right-hand one. There are three ways to make one, and they exist because dragging precisely onto a small dot is hard on a trackpad and impossible on a touch screen.

  • Drag between ports. The drop is magnetic within roughly seventy pixels, so you do not have to hit the dot exactly.
  • Drag onto the node. Releasing anywhere over a target node connects to that node's first input port.
  • Click, then click. Click an output port, then click either an input port or anywhere on the target node. Clicking empty canvas or pressing Esc cancels.

An input accepts one incoming wire. Connecting a second one silently replaces the first rather than stacking them — this is the single most common source of "my edge disappeared". Two places break that rule on purpose: a container's end handle, where the branches of a loop body converge back, and the Join node's input, which waits for all of them.

An existing wire can be re-routed by dragging either of its endpoints onto another handle. Dropping an endpoint in empty space deletes the wire. Separately, starting a drag on an input port that already has a wire lifts that wire off and lets it follow the cursor; dropping it on another node moves its destination there, and dropping it on nothing at all puts it back where it was.

A drop that cannot connect explains itself in a toast at the bottom of the canvas rather than doing nothing. The messages are short and literal: Start the connection from an output port, A node can't connect to itself, Drop onto a node inside the container, not the container itself, and That node has no input port to connect to. Releasing over empty canvas is treated as an ordinary cancel and stays quiet.

Selecting and moving

Left-dragging on empty canvas draws a selection box, and a node only has to be touched by that box to be selected. Panning is on the middle and right mouse buttons. Shift or Ctrl adds to a selection, and Ctrl+A selects every node.

Clicking a node also pins its data wires on (see the density control below), which is why a single click makes dashed lines appear. Double-clicking has a per-type meaning: a Sub-flow node drills into the workflow it calls, an Inline Code node opens the code editor, and a Condition node opens the full-screen logic editor. Double-clicking anywhere else zooms.

The property inspector

The upper right panel configures whatever is selected. Its header shows the node's display name and its node id — worth noting, because that id is what expressions reference — plus a delete button. The form itself is generated from the node package's manifest, so the fields you see are the fields that node actually declares; a few node types (HTTP Request, Scheduler, Polling Trigger, Resource Picker, imported OpenAPI operations, Sub-flow) render a purpose-built form instead.

Above the form, two sections appear when they have something to offer. Insert data reference lists the outputs of every upstream node as clickable chips that copy a ready-made {{ … }} expression to the clipboard. Signal fields appears on graphs started by an external device or an event or action trigger, and offers the fields that signal carries. Below the form sit the Node I/O inspector and the Pin Output editor, both described in Expressions and data.

Selecting an edge instead of a node swaps the panel for a connection summary: the source node and output handle, the target node and input handle, and a delete button. If a node's type has no active package manifest the panel says so plainly and shows no fields, which is the signal that the workflow references a node package that is not installed.

The whole right-hand column is resized by dragging its left edge, between 300 and 820 pixels wide, and the width is remembered.

Align, distribute and Tidy

The floating toolbar at the top right of the canvas holds the layout tools. Alignment buttons appear once two nodes are selected (left, horizontal centres, right, top, vertical centres, bottom); distribution buttons appear at three (horizontal, vertical). Both apply as a single undo step.

Tidy re-lays the entire graph left to right and then re-frames the view. It is container-aware: the body of each loop or parallel container is arranged inside its container, and a container is never shrunk below its current size. Because it moves every node it is one undo step, and undo puts every position back.

A workflow loaded without saved coordinates — a gallery example, a fresh import, an AI-generated graph — is tidied automatically once the browser has measured the nodes. That automatic pass is not an edit: it records no undo step and does not mark the workflow as changed.

Center frames all nodes. Grid toggles snap-to-grid, which is Off by default and uses a 24-pixel step matching the dot pattern in the background, so a snapped node's top-left corner lands on a dot. Snapping applies to dragging, dropping, pasting and Tidy alike.

The data-wire density control

Reading a variable does not draw a normal edge, because the value does not travel along the control flow — it is fetched from the workflow's variable store. The editor still shows those reads, as dashed wires between the node that produced a variable and each node that consumes it. Because a busy graph can have a great many of them, the eye button at the bottom right of the canvas chooses how much is drawn.

ModeWhat is drawn
Reveal on demand DefaultOnly the execution flow. Data wires appear when you hover or click a node or a variable.
Compact dotsDashed data wires always visible, each collapsed to a small diamond at its midpoint.
Always-on value boxesDashed wires plus the full value token on every one.

Clicking a node or a variable pill pins its wires so they stay visible in any mode; clicking empty canvas or pressing Esc clears every pin. The chosen mode is remembered across sessions and applies to every workflow, not just the open one.

Sticky notes and groups

Both are editor-only annotations. They have no ports, are registered on the backend as no-ops so they survive save, publish, versioning and restore like any other node, and they never execute.

Note on the toolbar drops a sticky note at the centre of the current view, selected and ready to type into. A selected note can be resized (down to 140 by 90 pixels) and recoloured from five swatches. In a read-only view the text is shown but cannot be edited.

Group appears once two or more nodes are selected and wraps them in a tinted frame. A group is purely visual — it does not change execution — but it does own its members: moving the frame moves everything inside it, and membership is stored on each child, so it survives a save. Groups can be renamed by double-clicking the title or using the pencil, tinted with one of five colours for categorisation, and collapsed to a compact chip that shows the name and a live child count. Ungroup returns the children to the top level.

Resizing an expanded group from its top or left handle moves the frame's origin; the children are shifted back by the same amount so they stay exactly where they were on the canvas.

Finding a node

Ctrl+F or Ctrl+K (⌘ on macOS) opens a jump palette that filters the nodes on the canvas by title. Arrow keys move through the results, Enter jumps to the highlighted one, and Esc closes. Picking a result centres the canvas on that node at a fixed zoom and selects it, which also brings its properties up on the right.

This shortcut is allowed even while a text field has focus, so it can always be summoned; once open, the palette owns the keyboard.

Undo and redo

Every structural edit records a snapshot before it happens, and compound gestures collapse into one step: a drag that moves a node, a drop that also auto-connects, a Tidy that moves fifty nodes, an extraction that rewrites the graph. A drag that does not actually move anything records nothing.

The history keeps up to 100 steps in each direction and is reset when a different workflow is loaded — it is not a cross-workflow timeline. Undo and redo are ignored while the cursor is in a text field, so typing in a property field and pressing Ctrl+Z undoes your typing, not your last wire.

Leaving with unsaved changes

The editor compares the current graph against the last saved state, ignoring things that do not affect the definition. Pressing Back with pending edits opens a dialog offering Cancel, Discard & leave and Save & leave. Closing or reloading the browser tab instead gets the browser's own native "leave site?" prompt.

Only the canvas Back button is guarded

The dialog is wired to the editor's own Back button. Navigating away with the header tabs — to the dashboard, settings, or anywhere else — leaves the editor without asking, and unsaved canvas edits are lost. Save before switching screens.

Editing a sub-flow behaves differently: leaving a sub-flow always saves and publishes it first, so the caller picks up its current interface. See Sub-flows and grouping.

Read-only version preview

Picking an older version in the Runtime version dropdown does not activate it. It opens a read-only preview of that version's graph: an amber banner appears, the canvas is rendered at reduced opacity, and dragging, connecting and selecting are all disabled. Your working draft is untouched underneath and returns when you exit.

From the banner you can Diff the previewed version against your draft, or Restore this version, which makes it the current live version and brings its content back into the draft. Restore is hidden when the version you are previewing is already the active one. Esc exits the preview, unless a dialog or overlay is open, in which case that overlay gets the key first.

Run is still available while previewing — it targets the version you are looking at — but is disabled while a diff is open. Save & Publish is disabled throughout.

Save & Publish and Run

Save & Publish is one action with two effects: it persists the draft, then snapshots it as a runtime version and activates that version, so the workflow is immediately runnable. Identical content is de-duplicated on the backend, so re-saving an unchanged graph does not spawn a new version. The button reads Saved and is disabled when there is nothing new to publish; a workflow that has never been published can always publish its first version.

When the graph has blocking errors the button turns amber and reads Save & Publish (2 errors). It stays clickable on purpose — saving still keeps your draft — but publishing will be refused and the failure is written into the diagnostics panel rather than an alert box. See Diagnostics.

Run activates whichever version is selected in the dropdown and then triggers it, so what executes is always what the dropdown says. It needs at least one published version; until then it tells you to publish first. Starting a run does not navigate away: a small Run started toast appears with a link to the execution view, node status is painted onto the cards on the canvas as the run progresses, and the variable pills fill in with real values in place.

Painted run status is cleared whenever the graph's behaviour changes — nodes, edges or properties — but survives a pure move, because repositioning a node does not invalidate what the last run did. It is also cleared on save and at the start of a new run.

Event-driven graphs have no Run button

A workflow built from external device blocks with no Start or manual trigger has nothing for a manual Run to start. The Run button is replaced by an Event-driven badge, a Watch live runs link into the execution viewer, and a Simulate signal button that fires one of the wired device pins with sample values. Remember that live event runs need the runtime armed — and opening the editor disarmed it.

Keyboard shortcuts

The full list is also available in the editor by pressing ?. On macOS Ctrl is ⌘ throughout.

Everything except the search palette and the history panel is ignored while a text field has focus, so ordinary typing is never intercepted. Copying and pasting carries the whole selected subgraph, with fresh node ids and the internal wires rebuilt.
