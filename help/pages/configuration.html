Configuration reference

Every setting Knotarium reads at startup, what it defaults to, and what changing it actually does. Most instances need none of this — the defaults are chosen so a fresh install works with no configuration at all. Reach for this page when you are running as a service, sharing data between installs, hardening an instance, or tracking down where your data went.

How settings are loaded

Settings come from several sources, each overriding the one before it:

  1. appsettings.json, next to the executable.
  2. appsettings.{Environment}.json — for example appsettings.Development.json.
  3. User secrets, in development builds only.
  4. Environment variables.
  5. Command-line arguments, which win over everything.

Environment variables use a double underscore to express nesting. A setting written as Storage:DataDirectory in a JSON file becomes Storage__DataDirectory as an environment variable, because a colon is not a legal variable-name character on most systems. Both forms are listed for every setting below. 

# The same setting, three ways

# appsettings.json
{ "Storage": { "DataDirectory": "D:\\KnotariumData" } }

# environment variable (PowerShell)
$env:Storage__DataDirectory = 'D:\KnotariumData'

# command line
Knotarium.Api.exe --Storage:DataDirectory "D:\KnotariumData"
Running as a Windows service

Under the service manager the application pins its content root to the executable's own folder, so appsettings.json is always found regardless of the working directory the service was started with. Environment variables must be set for the service account, not for your interactive session — this is the most common reason a setting appears to be ignored.

Where your data lives

This is the setting worth understanding before any other. One machine-wide directory holds everything that must survive an upgrade: the SQLite database, the encryption key that protects stored credentials, your workflow drafts, and the export folder.

Because the location is machine-wide rather than per-user, an interactive run and a Windows service running under a different account share the same database — which is what you want, and is the reason the default is %ProgramData% rather than a profile folder.

Back up the credential key with the database

.credential-key is what decrypts every stored password, token and API key. A backup of Knotarium.db without it leaves you with credentials that can never be read again. The two belong together.

Migration from older versions

Earlier builds kept workflow drafts in the per-user %APPDATA%\Knotarium folder. On every non-development startup Knotarium checks that old location and moves what it finds into the current data directory:

  • Draft files from %APPDATA%\Knotarium\workflows\ move into <data directory>\workflows\.
  • groups.json moves alongside them.
  • A file whose name already exists in the destination is left where it is and logged as a warning. Nothing is ever overwritten.
  • The old workflows folder is removed once it is empty. The %APPDATA%\Knotarium folder itself is left alone.
  • If the move fails — a permissions problem, a file in use — startup logs a warning and continues rather than refusing to start.
Only drafts are migrated

The migration moves workflow drafts and the group file. It does not move a database. If you are upgrading from a build that kept Knotarium.db next to the executable, that file stays where it is and the new version starts with an empty database in the data directory. Copy the old Knotarium.db — and its .credential-key, if one exists — into the data directory yourself before first launch, or point Database__ConnectionString at the old file.

Storage settings

SettingTypeDefaultEffect
Storage__DataDirectory path %ProgramData%\Knotarium Machine-wide home for the database, credential key, drafts and exports. Docker images set it to /data. The folder is created on startup if missing.
Storage__MinFreeSpaceMb integer 256 Free-space floor. When the drive drops below it the runtime disarms itself and stops firing automatic triggers. It does not re-arm on its own once space is freed — you re-arm it deliberately.
Storage__FreeSpaceCheckSeconds integer 60 How often free space is sampled.

Database

SettingTypeDefaultEffect
Database__Provider string SQLite Which storage provider to use. SQLite is the only implemented option; a Postgres provider exists as a scaffold behind the same interface but is not usable yet.
Database__ConnectionString string Data Source=<data directory>/Knotarium.db Overrides the database location. Setting this moves only the database — the credential key still lives in the data directory, so the two can be separated by accident. Prefer changing Storage__DataDirectory unless you specifically need them apart.

Authentication

SettingTypeDefaultEffect
Auth__Enabled boolean true Cookie sign-in. On first start with no accounts the browser is asked to create an administrator. Turning it off makes every endpoint anonymous.
Auth__InitialAdmin__Username string unset Seeds the first administrator without a browser, for unattended installs. Applied only when no accounts exist.
Auth__InitialAdmin__Password string unset Password for that seeded account. Supply it through a secret store rather than a checked-in file.
Disabling sign-in is restricted to loopback

If Auth__Enabled is false while the instance is bound to anything other than localhost, startup fails on purpose. An unauthenticated Knotarium reachable from the network is a remote code-execution service for anyone who finds it. The override that lifts this check, Security__AllowUnauthenticatedNonLoopback, exists for isolated test harnesses — it is not a deployment option.

The session cookie itself is not configurable: it is named kg_auth, marked HttpOnly with SameSite Lax, restricted to HTTPS outside development, and slides forward on a seven-day expiry.

Credentials and package signing

SettingTypeDefaultEffect
Security__Credentials__EncryptionKeyBase64 base64, 32 bytes auto-generated The key encrypting stored credentials at rest. Left unset, one is generated into <data directory>/.credential-key on first use and reused forever after. Set it only to bring your own — and then never change it, or every saved credential becomes unreadable.
Security__PackageSigning__HostPrivateKeyBase64 base64 unset Private key used to sign bundles and node packages you export. Only needed if you publish packages for others.
Security__PackageSigning__TrustedPublicKeys string array empty Public keys whose signatures are accepted when importing a bundle or package.
A second name for the same key

The credential key is also read from a standalone environment variable, Knotarium_CREDENTIAL_ENCRYPTION_KEY_BASE64, which does not follow the Section__Key convention. Either name works and they mean the same thing; if both are set, the standard configuration key takes precedence.

Network egress and request policy

These settings govern what the instance is allowed to talk to, and who is allowed to talk to it. They apply to the HTTP Request node, AI provider calls, and every other outbound request the engine makes.

SettingTypeDefaultEffect
Security__HttpEgress__DenyPrivateNetworks boolean true Blocks outbound requests that resolve to private, loopback or link-local addresses, and re-checks after DNS resolution so a hostname cannot be rebound to an internal address mid-request. Turn this off only on a network where reaching internal hosts is the point.
Security__HttpEgress__AllowDomains string array empty When non-empty, outbound requests may only go to these domains. Empty means no allow-list is applied.
Security__HttpEgress__BlockDomains string array empty Domains that are always refused, checked after the allow-list.
Security__EnforceSameOrigin boolean false Rejects authenticated state-changing requests whose Origin header does not match this host. Off by default because a reverse proxy that rewrites Host produces false rejections; safe to enable when the instance is bound directly.
Security__AllowUnauthenticatedNonLoopback boolean false Lifts the startup check that forbids running without sign-in on a non-loopback address. See the warning above.
Security__RateLimit__LoginPerMinute integer 10 Sign-in attempts allowed per minute, throttling password guessing.
Security__RateLimit__AnonymousMachinePerMinute integer 60 Anonymous machine-to-machine requests per minute — inbound webhook triggers and run resumption. Raise it if legitimate webhook traffic is being rejected.
Cors__AllowedOrigins string array empty Empty allows any origin but refuses credentialed cross-origin requests. Listing origins switches to an allow-list that does permit credentials — needed only when a separate front-end origin calls the API.

Sandbox

User-authored C# — the Inline Code node and compiled custom node packages — runs either inside the main process or in pooled worker processes with operating-system limits. The Settings › Sandbox screen writes these same values to the database, and the stored values override the configuration below. Treat these keys as the starting point for a fresh instance.

SettingDefaultRangeEffect
Security__Sandbox__ModeInProcessInProcess or ProcessProcess runs user code in separate worker processes so a runaway script cannot take the engine down with it.
Security__Sandbox__AnalyzeAtRuntimetruebooleanRejects user code that calls banned APIs before it is allowed to compile.
Security__Sandbox__WorkerCount41–32Size of the worker pool in process mode.
Security__Sandbox__MemoryLimitMb51264–16384Memory ceiling per worker.
Security__Sandbox__CpuPercent1005–100CPU share per worker.
Security__Sandbox__MaxRunSeconds3001–3600Hard limit on a single sandboxed execution.
Security__Sandbox__KillGraceSeconds51–60Grace period between asking a worker to stop and killing it.
Security__Sandbox__RecycleAfterRuns1001–10000Retires a worker after this many executions, bounding slow leaks.
Security__Sandbox__RestrictedTokentruebooleanOn Windows, runs workers with a restricted token at low integrity.
Security__Sandbox__ProxyCredentialstruebooleanKeeps decrypted secrets out of the worker process — the worker asks the host to use a credential rather than receiving it.
Security__Sandbox__MaxHttpResponseMb321–100Largest HTTP response sandboxed code may receive.

Retention

As with the sandbox, Settings › Retention overrides these once set.

SettingDefaultEffect
Retention__RunHistoryDays30Age at which finished runs and their journals are pruned. Zero or negative keeps everything forever, which grows the database without bound.
Retention__SweepIntervalMinutes60How often the pruning sweep runs.
Retention__MaxWorkflowVersionsPerWorkflow0Cap on retained published versions per workflow. Zero disables the cap.
Retention__MaxOpenApiSpecVersionsPerSpec0Cap on retained OpenAPI specification versions. Zero disables the cap.
Retention__AuditEntryDays0Age at which audit entries are dropped. Zero keeps them all. Enabling this rewrites the tamper-evident hash chain, so older entries can no longer be verified against the original chain.

AI

SettingDefaultEffect
Ai__MaxTokens8000Token ceiling for generating a workflow from a natural-language description.
Ai__MaxRepairAttempts3How many times a malformed generated workflow is sent back for repair.
Ai__MaxIntentLength4000Longest description accepted by the generator.
The provider itself is not configured here

Which vendor, which model and which API key the AI nodes use are stored in the database and managed from Settings › AI Provider, so the key can be held as an encrypted credential rather than sitting in a configuration file. The keys above only bound the workflow generator.

Hosting and addresses

SettingDefaultEffect
ASPNETCORE_URLShttp://localhost:43120Address and port to bind. Docker images use http://+:43120 to accept traffic from outside the container. Binding beyond localhost is what triggers the authentication check described above.
ASPNETCORE_ENVIRONMENTProductionLoad-bearing well beyond logging: Development changes where data is stored, relaxes the HTTPS-only cookie, refuses to auto-generate a credential key, and enables node hot-reload. Never set it to Development on a real instance.
AllowedHosts*Host header filter.

The port 43120 is Knotarium's default throughout — the installer, the Docker image and the desktop shortcuts all assume it. Change it with ASPNETCORE_URLS, or, for containers, by remapping the host side of the port publish instead: 

# Serve the UI on 8080 without touching the app's own configuration
docker run -d --name knotarium -p 8080:43120 -v knotarium-data:/data \
  ghcr.io/andrekfm/knotarium:latest
The Logging section has no effect

appsettings.json contains a Logging section, but application logging is configured in code and does not read it. Editing Logging__LogLevel__Default changes nothing. Application logs are emitted at information level, with database logging held down to warnings.

The KG_ variables work only with Docker Compose

Three shorthand variables appear in the project's documentation and Compose file:

ShorthandSets
KG_AUTH_ENABLEDAuth__Enabled
KG_ENCRYPTION_KEYSecurity__Credentials__EncryptionKeyBase64
KG_SIGNING_KEYSecurity__PackageSigning__HostPrivateKeyBase64
These are not application settings

The translation happens inside docker-compose.yml, not inside Knotarium. Setting KG_AUTH_ENABLED=false on a zip install, a Windows service, a systemd unit, or a plain docker run does nothing at all — and it fails silently, leaving you convinced sign-in is off when it is not. Outside Compose, always use the full setting name.

Settings the interface overrides

Four groups of settings can be changed at runtime and are then stored in the database. The stored value wins from that point on, and editing the configuration file will appear to have no effect:

  • Sandbox — Settings › Sandbox
  • Retention and disk space — Settings › Retention
  • Runtime arming — the switch in the header
  • AI provider — Settings › AI Provider

Everything else on this page is read once at startup, so changing it means restarting the application.

A minimal production configuration

For a Windows service sharing one database with interactive runs, on a machine where nothing else needs changing: 

{
  "Storage": {
    "DataDirectory": "D:\\KnotariumData",
    "MinFreeSpaceMb": 1024
  },
  "Auth": { "Enabled": true },
  "Security": {
    "EnforceSameOrigin": true,
    "HttpEgress": { "DenyPrivateNetworks": true },
    "Sandbox": { "Mode": "Process" }
  },
  "Retention": { "RunHistoryDays": 90 }
}

Leave the credential key unset so it is generated and stored beside the database, and back up the whole data directory as a unit.
